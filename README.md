# Medical-Triage

Educational classification of English medical abstracts into five medical
categories. This model does not predict clinical urgency and is not intended
for clinical use.

## Local monitoring stack

The stack runs the real saved model with FastAPI, Prometheus and a provisioned
Grafana dashboard. Run commands from the repository root.

Prerequisites: Docker with Compose, the project Python environment, and the
trusted local artifact `models/medical_triage_model.joblib` (not tracked in Git).
If the artifact is missing, obtain the original CSV files under `data/raw/` and
run the following commands. Training refuses to overwrite an existing artifact.

```bash
python -m pip install -c constraints.txt -e ".[dev]"
python scripts/prepare_data.py
python scripts/train_model.py --output models/medical_triage_model.joblib
docker compose -f compose.monitoring.yaml up -d --build
```

Stop any older API container occupying port 8001 before starting this stack.
The monitoring Compose uses a separate project name from the Airflow stack.

| Service | Local URL |
| --- | --- |
| API documentation | http://127.0.0.1:8001/docs |
| Metrics | http://127.0.0.1:8001/metrics |
| Prometheus targets | http://127.0.0.1:9090/targets |
| Grafana dashboard | http://127.0.0.1:3000/d/medical-triage-api |

Grafana's initial local login is `admin` / `admin`; change the password when
prompted. The ports bind to loopback only. This configuration is a local demo,
not a hardened public deployment. Grafana provisioning installs the datasource
and dashboard automatically; no manual import is needed.

Generate about one minute of demo traffic:

```bash
python scripts/generate_monitoring_traffic.py
```

One in ten calls intentionally contains blank text and should return 422.
This illustrates client errors; it is not a server failure. The dashboard
separates 4xx and 5xx error percentages. No internal failures are deliberately
generated by this script.

Dashboard panels show prediction request count since process startup, request
rate, p50/p95 processing duration, client/server error percentages, and scrape
availability. Only `/predict` contributes to prediction panels. Health checks
are collected separately, and `/metrics` requests are excluded.

Prometheus scrapes every five seconds. Generate traffic and allow several
scrapes before interpreting rate/percentile panels. With no traffic, latency
percentiles can be empty. Counters reset on API restart. Histogram percentiles
are approximations; durations are server-side, including response-body handling,
and differ from the client's end-to-end benchmark latency.

Metrics contain only bounded method, matched route, and status labels. Unknown
paths use `unmatched`; medical text is never included in metric labels. The
configuration supports a single API worker. Multiple workers/replicas require
additional Prometheus configuration and are not validated here.

```bash
docker compose -f compose.monitoring.yaml ps
docker compose -f compose.monitoring.yaml logs --tail=50 api prometheus grafana
python -m ruff check src tests scripts
python -m pytest tests/ -q
docker compose -f compose.monitoring.yaml down
```

Stopping the stack retains the named volumes. Do not add `--volumes` unless you
intend to delete the monitoring history and Grafana settings. Dashboard JSON
and provisioning YAML are versioned under `monitoring/`.
